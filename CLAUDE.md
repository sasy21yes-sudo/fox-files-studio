# CLAUDE.md — The Fox Files Studio

Context for Claude Code. Read this first; README.md has the user-facing feature list.

## Working with Salvatore (the owner)

- **Reply in Italian.** Code, comments and commit messages stay in English.
- He is a developer, wants the **highest visual quality** ("stile Cuphead": fluid, detailed, rubber-hose 1930s cartoon) and a **catchy Vox-style explainer** narration that keeps viewers glued — but every fact must stay true to the sources (`src/data/sources.ts`). ## What it is

Browser-only (Vite 7 + React 19 + TypeScript strict) editor that produces one animated documentary episode, *MKUltra: The Secret Experiments*, starring Agent Fox. Outputs 16:9 (YouTube) and 9:16 (Short with a cold-open hook) as real MP4/WebM, rendered in the browser.

```bash
npm install
npm run dev            # http://localhost:5173
npm run build          # typecheck + production build (dist/, relative base './')
```

## Architecture — the rules that matter

- **One renderer for everything**: `renderFrame()` in `src/animation/renderScene.ts` draws a frame at a global time. Preview, thumbnails and both exporters call it, so it must stay **deterministic** (no wall clock, no Math.random without a seed — use `hash()` from `animation/math.ts`).
- **Timeline** (`src/animation/timeline.ts`, `buildTimeline(project, rate, voice)`): scenes → spans, narration → sentences (`splitSentences`) → subtitle cues (`splitSentence`, ≤13 words, split at a mid clause). With the studio voice, real clip lengths drive cue times exactly, cues change at the voice's pauses, and a scene **extends** if the voice needs more room. `tl.level(t)` = voice loudness for lip sync. Choreography is authored in short "authored seconds" (`CHOREOGRAPHY_LENGTH` in `data/mkultraProject.ts`) and time-stretched: `k = choreoTime(span, local)`.
- **The Short's own cut** (2026-10-25): `project.short = { enabled, clips: [{ scene, from, to }] }` (sentence indices of the scene's narration, `splitSentences`). `buildShortTimeline()` cuts those sentences out of the 9:16 episode (picture via `SceneSpan.offset`/`fullDuration`, voice clips, cues, pop-ups, scene sfx, lip-sync level) after the hook, without chapter cards (`tl.short`). The editor keeps the whole episode's timeline; the preview plays the cut while "Preview the Short" is on (`editor/ShortPanel.tsx`, right column in 9:16); single export renders what the preview plays, the two-format export uses the cut for 9:16. QA: `node tools/qa/short_cut.mjs [lang]`, `SHORT=1 node tools/qa/review_kit.mjs it 9:16` (→ `qa-out/review/it_9x16_short`), `SHORT=1` for `frames_at.mjs`.
- **Channel page** (`editor/ChannelPage.tsx`, `/channel` skill): Dashboard (per-cut numbers, a heuristic retention forecast from `channel/forecast.ts` - an estimate, never presented as YouTube data - and real curves from YouTube Studio CSV imports analysed by `yt-retention/retention.py`), title/hook lint with the youtube-agent scripts (`tools/vite/channel.ts`), Brand kit (`channel/channel.json`; banner 2560x1440 and icon 800x800 drawn by `channel/brand.ts` from the rig and the series art), and a YouTube-page mock-up (also from the Team page). The youtube-agent skills (Jakeschincariol/youtube-agent-skill, MIT, reviewed: stdlib-only scripts) are in `.claude/skills/yt-*`.
- **Team chat, live and cheap**: the Team page gets messages by server-sent events (`/api/team/stream`, fs.watch on the chat file); agents read with `chat.mjs new --for <name>` (per-reader cursor, only unseen lines, others' text cut to 160 chars) and can block on `chat.mjs wait --for <name>` for a reply.
- **Team page chats**: "Everyone" = the whole team chat; each agent = a private chat (Salvatore <-> that agent). With "Live answer" the agent replies at once through `POST /api/team/ask` (`tools/vite/teamAsk.ts`): the local Claude Code CLI, Sonnet, low effort, no tools ("May read the files" adds Read/Grep/Glob), the agent's .md as system prompt and only the last 12 lines of that chat + the producer's brief (~3k tokens a reply, measured 2026-10-26). Answers may run to 1200 chars.
- **Tools page** (`editor/ToolsPage.tsx`, `tools/vite/skillTools.ts`): every skill in `.claude/skills` with Use (ready forms for title.py, hookscore.py, retention.py prefilled from the episode; a generic runner for other scripts: only .py inside that skill, argument list, no shell, 90 s), a step-by-step Tutorial built from its SKILL.md, and the full instructions. `first-customer-finder` (Kappaemme-git, MIT, reviewed) is installed; `yt-sponsors` adapts it to sponsors and only runs when Channel > Brand kit > "Ready for sponsors" is on (`channel.json collaborations`), never sending anything.
- **Episode sync safety**: a browser that never synced an episode always loads the repository's (its own version becomes "(local copy)"); a fresh QA browser's default project once overwrote the edited episode (2026-10-25).
- **Scenes are data or code.** A scene with `spec` (a `SceneSpec`, `src/scene/spec.ts`) is drawn by `scene/renderSpec.ts` from an element library (`scene/elements.ts`: sets, props, effects over `animation/props.ts`/`effects/cartoon.ts`, each with label, description and params — the editor and Claude read this catalog), Agent Fox acting tracks, camera shots and overlays. Tracks follow the helpers' hold-then-transition rule (`scene/tracks.ts`); per-format numbers are `{h, v}`. `scene/validate.ts` gates anything stored, imported or produced by Claude. Scene 1 (`file`) is data (`data/specs/file.ts`, pixel-identical to the old `sceneFile.ts`: check with `tools/qa/spec_ab.mjs`); the other five MKUltra scenes are still hand-coded in `src/animation/scenes/scene*.ts` (+ `hook.ts`) and render when a scene has no spec.
- **Projects** (`data/project.ts`, schema v8): `template: 'mkultra'` (texts/translations from `i18n/scripts.ts`, via `data/projectText.ts`) or `'custom'` (everything in the project: narration, titles and pop-ups per language, hooks, sources). `data/library.ts` keeps many episodes in localStorage (index + one key each; v7 migrated) with .foxproj.json import/export.
- **Editor** (`src/editor/`): Media / Edit / Deliver pages; undo/redo over the whole project (`useHistory`, edits coalesced by key); multitrack `TimelineEditor` (global scene/pop-up/subtitle/voice/music tracks + the selected data scene's camera, Fox actions/arms/face and one lane per element); `Inspector` for elements, shots, actions, keys, pop-ups (scene settings stay in `components/PropertiesPanel`). Edits go through the immutable helpers in `editor/model.ts`; times on scene lanes are authored seconds (`toGlobal`/`toAuthored`).
- **Claude prompt editing**: `editor/AiPanel.tsx` (scope: the selected scene or the whole video) → `ai/claude.ts` → `POST /api/claude/edit`, served only by `npm run dev` via the Vite plugin `tools/vite/claudeScene.ts`. Backend: the local **Claude Code** CLI run headless (`claude -p --json-schema … --tools ""`, from a temp dir with no settings/MCP, session env vars stripped), found via `CLAUDE_CODE_BIN` in `.env`, PATH, `~/.local/bin` or the newest VS Code/Cursor extension — it uses the Claude Code login, no API key. Only if no binary is found and `ANTHROPIC_API_KEY` is in `.env` does it call the API (key read server-side, never sent to the page). Default model `claude-opus-5-5` (`CLAUDE_MODEL`), but the panel picks per request: Sonnet (default), Opus, Haiku, thinking effort low/medium (default)/high, "Web ideas" (WebSearch/WebFetch only when ticked). The system prompt is built from the element catalog + scene 1 as reference (static, so it is cached); the request carries every scene's narration (full spec/pop-ups only for the scenes in scope) and the sources with dates; the reply lists only the changed scenes, preferably as `spec_patch_json` (RFC 6902 add/replace/remove, array items addressed as `@<id>`, applied server-side by `applyPatch`) or the whole `spec_json` for big rewrites; each validated (spec, cues verbatim in that scene's narration, no scene outside the scope), with one corrective retry that resends text only; all changes apply as one undo step. Hand-coded scenes can get new pop-ups/length without losing their coded picture. Claude also SEES the scenes: `ai/frames.ts` renders frames with `renderFrame` (640 px, ~300 tokens each; 3 per scene, 1 per scene for the whole video) and they go INSIDE the message - image blocks to the API, `--input-format stream-json` to the CLI (never as files to Read: one tool turn per frame re-sent all earlier frames, the main token waste found on 2026-10-25). "Check the result" (off by default: it is a second request) renders the edited project and asks again with `review` set. The panel shows new / cached input, output and USD (also for failed requests). Cost of one request: `node tools/qa/ai_cost.mjs <scene|all> "<prompt>" [model] [effort] [frames]` - measured 2026-10-25, Sonnet/medium/3 frames: ~22k in, ~350 out, $0.05 warm / $0.09 cold.
- **Images**: `project.media` lists library images (`MediaItem`); the pixels live in IndexedDB (`media/store.ts`, shared by all episodes in the browser) and are decoded into a cache the synchronous renderer reads. Anything rendering for output must `await loadProjectMedia(project)` first (export and stills do). Project files embed them as data URLs (`mediaData`). The `picture` element (Ken Burns zoom/pan over its visible time, cover/contain, photo frame, `layer: 'screen'` = drawn above the scene outside the camera, for cutaways); `pictureSpec()` makes a one-image cutaway scene (`chapterCard: false`). Generation: `editor/ImageBin.tsx` → `ai/localImage.ts` → `POST /api/image/generate`, Vite plugin `tools/vite/localImage.ts` → local ComfyUI (`COMFY_URL`, default 127.0.0.1:8188) with Qwen-Image-Edit-2511 used text-to-image (empty latent, Lightning 8 steps, ~30 s), queued at the front so asset batches do not block it. The model misspells words: prompts always forbid text; words go on stamps/papers/pop-ups. Generated pictures are illustrations, never to be presented as archive documents.
- **Preview handles**: `renderFrame(..., { probe })` records where a data scene's elements land (`RenderProbe`: camera matrix, screen matrix, anchors); `editor/StageOverlay.tsx` draws handles from it (paused only) — click selects, drag moves x/y in the format on screen only (`setNumFor` splits a shared value into {h,v}), one undo step per drag. Ctrl+C/V/D copy/paste/duplicate elements; `?` lists shortcuts; "Still" saves a full-resolution PNG.
- **Explainer pop-ups ("beats")**: `src/effects/beats.ts`, defined per scene and language in `src/i18n/scripts.ts`; each beat triggers on a phrase (`cue`) found in the narration text.
- **Agent Fox**: `src/character/AgentFox.ts` (+ `rig/rigPuppet.ts`). Painted cut-out rig from baked sprites in `src/character/rig/` (rubber-hose "noodle" limbs strip-mapped along a curve, band warps for spine/coat/tail, pie-cut procedural eyes, 12 mouth drawings, gloves mirrored with flipY). Near arm = character's left, lighter, drawn ABOVE the torso with no shoulder cap; far arm behind. A vector rig remains as fallback (`characterStyle: 'vector'`). Per-arm, per-pose overrides live in `rig/tweaks.json` (model sheet → "Tune poses & motion" for hand target/rotation/layer, "Hands" (`editor/HandLab.tsx`) for the glove: `mirror` auto|yes|no, `handScale`, `anchor` [along, across] in sprite px = the attach point against the sleeve, `handTurn`, `hand` drawing); `armDef()` merges them over `FAR_T`/`NEAR_T`. "Hands" also has a Drawings view like Mouths (`editor/HandDrawings.tsx`, `/api/rig/hands*` in `tools/vite/rigTools.ts`: run_jobs.py hands_new_back|front, edit.py --mark, bake_rig.py). "Shoes" (`editor/ShoeLab.tsx`) sets per leg `legs.{near,far}`: `anchor`, `shoeScale`, `shoeTurn`. The front bust (`foxFront.ts`) does not use any of them yet.
- **Languages** (`src/i18n/`): en, it, es, fr, pt(-BR). `scripts.ts` holds narration, titles, keywords, beats, hook and TTS pronunciation hints (`say`). On-screen labels are drawn as English literals and translated at the canvas level (`labels.ts` patches fillText/strokeText/measureText; dictionary in `labelStrings.ts`; `wrapText` translates before splitting). New on-screen text → add it to `labelStrings.ts` for all four languages and run `npm run qa:labels -- <lang>`.
- **Studio voice** (`src/audio/studioVoice.ts`, voices in `studioVoices.ts`): Kokoro-82M packs in `public/voice/<lang>-<voice>.{mp3,json}`, rendered offline. Rewritten sentences missing from the pack are rendered live by `tools/voice_server.py` (127.0.0.1:8765, auto-probed only when the app runs on localhost) or read by the browser voice in preview (silent in export). Other local engines tried for Italian (samples by `tools/tts_samples*.py`, each in its own venv under `C:/Users/Admin/AI/tts/`): Qwen3-TTS (`.venv`, pack `it_qwen_narratore`), Chatterbox Multilingual (`chatterbox`, MIT; needs `setuptools<81` for its Perth watermark; the default voice mispronounces a few words, Whisper-checked) and VoxCPM2 (`voxcpm`, Apache-2.0, voice designed from a description in parentheses; transcribes cleanly). Higgs Audio v3, Voxtral TTS, Fish Speech and XTTS speak Italian but their weights are non-commercial only — not for a monetised channel.
- **Music**: `src/audio/ambience.ts`, original hot-jazz score synthesised sample by sample (direct DSP — never go back to OfflineAudioContext node graphs, they took 300 s), ducked under every cue. Users can load their own track (`fitMusicTrack`).
- **Export**: `src/export/` (WebCodecs MP4 via mp4-muxer, or MediaRecorder). Narration (studio track or file) and music are mixed in `audio/audioCapture.ts`.

## Episodes in the repository (editing a video remotely)

The editor's episodes live in the browser (localStorage + IndexedDB for images) **and** in `episodes/`: the dev server (`tools/vite/episodeSync.ts`) writes every save to `episodes/<id>.foxproj.json` (images in `episodes/media/<mediaId>.<ext>`), commits only that folder ("Episode: … (edited in the studio)") and pushes on the branch the dev server runs on. Every 45 s it pulls (fast-forward or merge, never touching other files); episodes changed by a pull or on disk reload in the open editor as an undoable step (header pill "Repo · <branch>").

To change a video from a remote Claude Code session: edit the episode JSON, commit, push — the local editor picks it up within a minute.
- Format: `Project` in `src/types.ts`; each `scenes[i].spec` is a `SceneSpec` (`src/scene/spec.ts`) — the same data the in-app "Ask Claude" edits, whose rules are spelled out in `systemPrompt()` in `tools/vite/claudeScene.ts` (read it before editing a spec). Times in a spec are the scene's authored seconds.
- Keep `id` unchanged. MKUltra episodes take their titles from the script (`src/i18n/scripts.ts`): edit narration/beats there or in `scenes[i].narrations[lang]` / `beatsByLang[lang]`. A beat's `cue` must be an exact phrase of that scene's narration. Facts only from `src/data/sources.ts`.
- An invalid spec is replaced by the scene's default when the page loads it (`restoreProject`), so keep to the types exactly; pictures must be listed in `media` and exist in `episodes/media/`.
- Sound effects: `spec.sfx` = `[{at, sound, gain?, pan?, count?, every?}]` in authored seconds; sounds and their use in `src/audio/sfx.ts` (`SFX_SOUNDS`), synthesised and mixed by the studio.
- Narration: change `scenes[i].narration` freely (facts from the sources only). When the local editor opens the episode, the dev server re-records the missing lines with the episode's studio voice (`tools/vite/voiceRecord.ts`: Kokoro on the CPU, Qwen3 on the GPU) and commits the new pack in `public/voice/` — a remote session never needs audio tools.
- `.env`: `FOX_EPISODE_GIT=off` (files only), `FOX_EPISODE_PUSH=off` (commit, never push).

## Layers (After Effects features) and frame-by-frame clips

- `src/scene/layers.ts` draws every data-scene element through a layer engine: `parent` (+ invisible `null` elements), `scaleBy`, `wiggle`, `repeat` (loopOut), `blend` modes, `fx` (blur, glow, shadow, color, tint, stroke, opacityFlicker), `mask` (feathered path), `matte` (alpha/luma, inverted; source has `isMatte`), `motionBlur`. Elements without them take the old direct path (pixel-identical). Keys accept Bézier eases `[x1,y1,x2,y2]` and `hold`. New elements: `text` (per-letter animators), `null`, `sprite`. Claude's prompt (`tools/vite/claudeScene.ts`) documents all of it; the Inspector has a Layer panel, an effects stack and a JSON editor.
- Frame-by-frame clips ("sprite" element): full drawings in `public/clips/<id>/` (atlas.webp + clip.json, index.json), built by `python tools/clips/build_clip.py <frames dir|sheet> --id ...` or from the model sheet → Clips tab. Every drawing is registered to the first on a locked region (default: the feet) with sub-pixel ECC; the build refuses a clip whose residual exceeds `--max-error` (0.25 px). QA sheets in `qa-out/clips/<id>/`. Playback counts exact ticks (fps + per-drawing holds; on twos by default). `demo_wave` is a pipeline test made from rig drawings, not hand-drawn art.
- Making clips locally (ComfyUI on 127.0.0.1:8188): key drawings by chained Qwen edits (`tools/comfy/edit.py` in the assets repo, each key edited from the previous one so the body stays put; start from an approved pose in `art/incoming/pieces/poses_key/` — separate generations differ in scale and line, never interpolate between them). In-betweens: `tools/clips/inbetween.py` (FILM, `film_net_fp16`) only for small moves with nothing uncovered; FILM melts anything that moves over something hidden (a lifted hat over the ears) and cross-fades two different hands into a ghost. For a move with a rigid prop use `tools/clips/prop_inbetween.py`: it needs each key plus a bare twin without the prop (Qwen "remove only the hat"); FILM moves the bare body, the prop and the hand holding it ride on as the keys' own drawings (pivot = glove centroid, turn/scale from the prop's long axis, drawing swapped halfway), everything that does not move stays key A's pixels, legs locked; `--ears` + `--ear-stretch` add secondary action (ears squashed under the hat, popping up with overshoot). Keep both keys' mouths the same drawing (a cross-faded mouth reads as a smudge; AI laughing mouths grow odd teeth). `tip_hat` (keys `anim_tip2/keyA_v4`, `lift_v1`, bare `bareA_v1`, `bareL_v5` in the assets repo) was made this way.
- Big limb moves (an arm travelling more than ~40 px): `tools/clips/limb_puppet.py` poses the limb of ONE drawing as a two-bone puppet (`--joints` shoulder, elbow, wrist in px; `--poses "upper,fore;..."` degrees per drawing, clockwise +; the hand and its prop ride on the forearm). Needs the drawing's limb-less twin (Qwen "remove his ... arm, as if hidden behind his back" — it often draws the arm hanging instead, which is fine: only the limb's own area is taken from the twin). Exact inverse skinning (Newton), cut edges re-inked, `--cover R` lays the coat back over a turned shoulder's root. It can only show what the drawing has: an upper arm hidden behind the coat cannot be swung out (keep such moves within ~35°). Qwen cannot draw in-between arm poses (asked for "halfway" or a target dot it keeps the pose or switches to the other arm — check which arm it moved). `magnify_peek` (from `poses_key/magnifier_v4`) and `point` (from `poses_key/point_v1`) were made this way. Debug images in a frames folder start with `_` (build_clip skips them). What a move had to make up (cut edges, the seam where a turned shoulder meets the coat) is redrawn by AI: `limb_puppet.py --fill-masks` writes `_mask_fNNNN.png`, then `tools/clips/genfill.py <dir>` repaints only inside each mask with Qwen-Image-Edit (crop ×3, latent noise mask, the drawing itself as reference, same seed for all drawings; originals kept as `_orig_`; `--only fNNNN --seed N` redoes one that came out soft). `point` was finished this way.

## Lessons from past feedback (don't repeat)

- Never paste a face over the head drawing (a second silhouette showed through) and never "reconstruct" his drawings — trace/use his parts. A reconstructed face was called "spaventoso".
- Arms must look like uniform rubber hoses when bent (no toy-like segments); thumbs must face the body; elbows bend down/outward when holding the magnifier.
- Static = bad: every shot needs overlapping action (body, tail, coat bend; head lag; hat follow-through).
- Pacing was "troppo veloce": keep breaths between sentences and let pop-ups explain.
- The first score was "troppo criptica": music must be catchy.
